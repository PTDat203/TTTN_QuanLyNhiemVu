# Thư mục `db/`

> **Database Oracle đang chạy là nguồn chuẩn duy nhất.**
> Code sửa theo database, không sửa database theo code.
> Ứng dụng **không** tạo bảng, **không** dùng EF Migrations — mọi thay đổi lược đồ là một
> script SQL đánh số, chạy tay bằng `sqlplus`.

## Kết nối

```text
Oracle Database 21c XE
Host: 127.0.0.1   Port: 1521   Service: XEPDB1   Schema: TASK_APP
Bộ ký tự: AL32UTF8
```

Luôn đặt `NLS_LANG` trước khi chạy script, không thì tiếng Việt bị hỏng mã lúc nạp:

```bash
export NLS_LANG=.AL32UTF8
sqlplus TASK_APP/<mat_khau>@localhost:1521/XEPDB1 @24_seed_v2.sql
```

### Dọn rác sau khi chạy bộ kiểm thử phân quyền

`kiem_thu_phan_quyen.py` tạo nhiệm vụ thật để kiểm quy tắc giao việc. Việc nào giao thành công
thì API không cho xoá nữa (chỉ xoá được khi còn "Mới tạo"), nên chúng ở lại database **ở trạng
thái đang mở**. Đó không phải chuyện nhỏ: khối lượng việc đang gánh là một thành phần chấm điểm
của mô hình gợi ý, nên rác tích lại sẽ đẩy người nhận xuống hạng một cách vô cớ và làm lệch cả
số liệu đánh giá.

Bộ kiểm thử tự xoá những việc nó xoá được và in ra id của phần còn lại. Dọn nốt bằng:

```bash
export NLS_LANG=.AL32UTF8
sqlplus -S TASK_APP/<mat_khau>@localhost:1521/XEPDB1 @25_don_rac_kiem_thu.sql
```

Script chỉ xoá nhiệm vụ trùng đúng tiêu đề mà bộ kiểm thử dùng **và** chưa từng có tiến độ hay
báo cáo, nên không bao giờ chạm vào dữ liệu nghiệp vụ thật. Nó in danh sách trước khi xoá.

### Còn nợ: bước thu hẹp lược đồ

Script 23 chỉ **mở rộng**. Hai việc để dành cho một script sau, khi ứng dụng đã chạy ổn trên
lược đồ mới:

- Bỏ `USER_SKILLS.SKILL_NAME`; đặt `SKILL_ID` là `NOT NULL` và thêm ràng buộc duy nhất
  `(USER_ID, SKILL_ID)`; sửa 21 nạp kỹ năng theo mã. Chưa làm ngay được vì 21 đang nạp theo
  tên — thêm ràng buộc duy nhất lúc `SKILL_ID` còn rỗng thì Oracle coi hai dòng `(5, NULL)`
  là trùng nhau.
- Bỏ `USERS.MANAGER_ID` — quản lý trực tiếp suy được từ nhóm và phòng.

### Khoá chính

11 bảng dùng `ID NUMBER GENERATED BY DEFAULT AS IDENTITY`; `TASK_STATUS_LOOKUP` dùng `CODE`.
Phía C#: `long Id` + `ValueGeneratedOnAdd()`. **Không dùng `Guid`.**

Script seed chèn ID tường minh nên luôn kết thúc bằng
`ALTER TABLE ... MODIFY (ID GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE))`.
Thiếu bước này thì INSERT đầu tiên từ ứng dụng xin lại ID = 1 và dính `ORA-00001`.

### Nhóm phải thuộc đúng phòng

`USERS` và `TASKS` có khoá ngoại ghép `(DEPARTMENT_ID, TEAM_ID)` trỏ về
`TEAMS(DEPARTMENT_ID, ID)` — `FK_USERS_TEAM_DEPT` và `FK_TASKS_TEAM_DEPT`. Database tự từ chối
một người phòng Nhân sự mà gắn nhóm Backend. Khi `TEAM_ID` rỗng thì khoá ghép không kiểm.

### Khoá ngoại và index

26 khoá ngoại, **cả 26 đều có index phủ** — kiểm bằng truy vấn dò khoá ngoại không có index
nào chứa đủ các cột của nó ở đầu (xem mục lệnh bên dưới). Oracle không tự tạo index cho khoá
ngoại; thiếu thì truy vấn theo cột đó quét toàn bảng và bảng cha bị khoá khi cập nhật.

Quy tắc xoá khác mặc định:

| Khoá ngoại | Khi xoá dòng cha |
|---|---|
| `FK_TASK_REQ_SKILLS_TASK` | `CASCADE` — ứng dụng có xoá nhiệm vụ `MOI_TAO`, đúng lúc AI vừa trích kỹ năng |
| `FK_TEAMS_LEADER` | `SET NULL` |
| `FK_DEPARTMENTS_HEAD` | `SET NULL` |

Còn lại là `NO ACTION`.

### Ngữ nghĩa chuỗi

Cả 35 cột `VARCHAR2` dùng ngữ nghĩa `CHAR`. `HasMaxLength(n)` trong EF Core ánh xạ 1:1 với
`VARCHAR2(n CHAR)`, không phải quy đổi byte.

## Lệnh kiểm tra nhanh

```sql
-- Đủ 12 bảng chưa
SELECT TABLE_NAME FROM USER_TABLES ORDER BY TABLE_NAME;

-- Tên cột và ngữ nghĩa chuỗi (CHAR_USED phải là C với mọi VARCHAR2)
SELECT TABLE_NAME, COLUMN_ID, COLUMN_NAME, DATA_TYPE, CHAR_LENGTH, CHAR_USED, NULLABLE
FROM   USER_TAB_COLUMNS ORDER BY TABLE_NAME, COLUMN_ID;

-- Khoá ngoại KHÔNG có index phủ — kết quả rỗng là đạt
SELECT c.TABLE_NAME, c.CONSTRAINT_NAME
FROM   USER_CONSTRAINTS c
WHERE  c.CONSTRAINT_TYPE = 'R'
  AND  NOT EXISTS (
         SELECT 1 FROM USER_INDEXES i
         WHERE  i.TABLE_NAME = c.TABLE_NAME
           AND  NOT EXISTS (
                  SELECT 1 FROM USER_CONS_COLUMNS fc
                  WHERE  fc.CONSTRAINT_NAME = c.CONSTRAINT_NAME
                    AND  NOT EXISTS (
                           SELECT 1 FROM USER_IND_COLUMNS ic
                           WHERE  ic.INDEX_NAME = i.INDEX_NAME
                             AND  ic.COLUMN_NAME = fc.COLUMN_NAME
                             AND  ic.COLUMN_POSITION <= (SELECT COUNT(*) FROM USER_CONS_COLUMNS x
                                                         WHERE x.CONSTRAINT_NAME = c.CONSTRAINT_NAME))));

-- Danh mục trạng thái
SELECT * FROM TASK_STATUS_LOOKUP ORDER BY SORT_ORDER;
```
